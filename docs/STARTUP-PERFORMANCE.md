# Windows 启动优化（2026-11-13）

桌面壳现在并行启动内置后端和 WebView2，同一个窗口先显示“正在打开书架”，后端就绪后直接进入书架。此前必须等后端健康检查成功后才创建窗口。

其他改动：

- 空闲端口先做 bind 检查，避免每次启动先等待一次失败的 HTTP 连接；本机探测绕过代理，新建后端的检测间隔由 250ms 改为 50ms，并允许随窗口关闭取消。
- 同时存在两种打包格式时优先使用目录版后端，避免误选需要每次解压的旧单文件版。
- 数据库只在创建应用时初始化一次，取消 lifespan 中重复的 schema 与迁移事务。
- 截图模式等待书架挂载后再计时，避免把启动占位页当成验收截图。

## 测量

在本机使用相同版本的后端比较修改前后的桌面壳。每轮创建临时空书库和独立 WebView 配置，交替运行三轮；这是新进程启动，未清空操作系统文件缓存。测量会启用仅用于验收的 WebView 调试端口。

| 毫秒 | 修改前 1/2/3 | 修改后 1/2/3 | 中位数变化 |
| --- | --- | --- | --- |
| WebView 可连接 | 828 / 738 / 722 | 253 / 251 / 215 | 738 → 251（约 -66%） |
| 空书架可操作 | 1011 / 942 / 930 | 834 / 789 / 706 | 942 → 789（约 -16%） |

WebView 可连接不等于首次绘制时间；书架可操作要求主页可见、骨架结束、空书架或书卡已呈现、没有加载错误。首次磁盘读取、杀毒扫描、机器性能和书库规模会改变实际耗时。

复现：`node scripts/measure-startup.mjs --exe dist/Velmira-desktop-v0.4.0/Velmira.exe`。

## 验证

- Go 单测与 vet 通过，覆盖目录版优先、旧版回退、健康检测取消/超时、复用服务及退出后保留外部服务。
- 自包含包的 `early-close` 和 `failure` 场景通过：可在启动等待中关闭；后端失败在当前窗口显示；退出后没有自建后端残留。
- Python 单测 132 项通过；最终内置后端在隔离书库中通过 41 项 API 检查和主页设置桌面/手机回归。
- APK、EXE、分发包、书库和 WebView 临时配置均不进入 Git。
