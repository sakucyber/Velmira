# 章节连续性记忆

Velmira 的记忆层在本地 SQLite 中保存，不依赖 DSH 或其他在线记忆服务。

每章分析完成后，文本模型单独读取本章原文并输出 `memory` 与带原文 `quote` 的 `facts`。胶囊限制为 100–250 token，这是硬约束；单条事实的引文改为分级降级：逐字命中保留，忽略空白/标点后可命中则保留并把 quote 修正为原文实际范围，仍无法验证的条目丢弃并记录，丢弃比例超过 40% 才带纠正提示重试，最后一次尝试保留所有可验证事实，不再因少数引文偏差中断整章。压缩不读取前一章胶囊，因此不会通过反复改写前情逐章累积失真。原文和完整章节分析仍保留。失败分类与诊断文件见 [AI-DIAGNOSTICS.md](AI-DIAGNOSTICS.md)。

事实类型包含事件、关系、物品、悬念与人物状态。每条事实保存章节、连续原文引用、引用的起止字符位置、角色、字段、值和原文版本哈希。不同变身阶段不会因语义相近被合并；同一引用出现多次时必须提供精确字符位置。`facts_before()` 以引用结束位置为界，不把尚未完整发生的变化用于前面的画格。每次读取还验证当前章节哈希，改动后的原文不会继续使用旧版记忆。

`snapshot()` 优先容纳当前人物与最近事实，再选择近期和相关历史胶囊；总预算默认 1800 token，按最终序列化上下文计数，包含来源、位置和元数据。当前章节的最终胶囊仅对下一章可用，不会提前透露本章结局。自动分镜只发送这一份上下文，不重复附带旧章节摘要或无时间位置的手工记忆。

已知模型使用 tiktoken 对应编码。未知模型使用 `o200k_base` 并标记 `estimated`。本地词表缺失时不联网下载，退回明确标记的 UTF-8 字节预算估计；部署时可预热 tiktoken 缓存，以获得实际编码计数。100–250 为当前已标明计数方法下的预算，不对未知远程模型声称精确一致。

胶囊、事实、章节分析在同一事务中提交；成功版本另外保存在 `chapter_memory_history`，源文本事实按来源和位置去重。失败或并发期间源文变化时保留旧版本。

设计参考 [dsh-mnemon](https://github.com/omdsh-dev/dsh-mnemon)：

- `plugins/dsh-mnemon-strategy-default-three-tier/src/strategy.ts`：常驻信息与按需历史分离、共享读取预算。
- `plugins/dsh-mnemon-strategy-default-three-tier/src/retrieval.ts`：固定读取视图、有限检索与证据去重。
- `plugins/dsh-mnemon-source-runtime/src/controller.ts`：压缩提交前的版本验证、先保留档案后更新工作记忆。
- `plugins/dsh-mnemon-provider-mnemon-native/src/driver.ts`：精确归档避免语义去重丢失相似但不同的状态。

本实现针对小说增加了原文字符时间线、状态阶段和严格 token 校验，没有直接复制其字符预算或用户偏好写入协议。模型可以正确引用文字却错误概括其含义；引用校验保证来源和位置，不能完全证明语义推理正确。原文与事实档案始终可用于复核。
