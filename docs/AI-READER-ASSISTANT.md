# AI 辅助阅读功能设计

> 支持纯文本模型读正文与漫画内容、概括大意、与读者对话
> 样本：《示例小说》51.6 万字 / 234 章 / 平均 2061 字每章

---

## 1. 一个前置判断

"纯文本模型读漫画"听起来矛盾，但在这个项目里**天然成立**：

漫画是我们自己生成的，画面的语义本来就存在于 `storyboard JSON`（谁在场、什么动作、什么表情、什么场景、哪句台词）里。文本模型不需要"看懂像素"，它直接读这份结构化描述即可——比 VLM 反推图片更准、更快、零成本，也不会幻觉。

所以分两条轨：

| 内容来源 | 语义来源 | 是否需要视觉模型 |
| --- | --- | --- |
| 本项目生成的漫画 | `storyboard` + `panel.prompt` + `page.layout` | **不需要** |
| 用户导入的外部漫画（CBZ/图片） | 逐格 caption，需 VLM 生成后缓存 | 需要（本机 `models/LLM` 为空，暂不可用；可接远程或用户自己的 llama.cpp） |

这条判断直接决定了成本结构：主路径不需要显卡跑视觉模型，只用文本模型。

## 2. 能力矩阵

| 能力 | 输入 | 输出 | 触发方式 |
| --- | --- | --- | --- |
| 本章概要 | 本章正文（+前情摘要） | 200–300 字中性摘要 | 读完自动 / 手动点 |
| 最近 N 章回顾 | L1 摘要链 | 500 字"前情提要" | 打开书时 / 侧栏 |
| 全书梗概 | L2 弧摘要 + L3 总纲 | 800 字 + 人物关系 | 目录页 |
| 分镜解释 | `panel` JSON + 原文片段 | "这一格在讲什么" | 点分镜卡 |
| 划词提问 | 选中文字 + 上下文 | 解释/背景/人物关系 | 选中浮动菜单 |
| 自由对话 | 检索 + 摘要 + 当前章 | 带引用的回答 | 右下抽屉 |
| 人物速查 | `character` 卡 + 出场章节 | 身份/关系/形态变化 | @ 提人物 |

## 3. 上下文构建（决定质量的地方）

### 3.1 三层结构

```
┌ 常驻层（每次都带，稳定、可缓存）
│   system 规则 + 全书 L3 总纲(150字) + 当前弧 L2 摘要(200字/弧，取最近 3 个)
├ 动态层（随位置变化）
│   当前章 L1 摘要(250字) + 当前章正文（可选，1550 token）
│   当前阅读位置之前 200 字的"上下文窗口"
└ 检索层（按问题取材）
    FTS5 命中 top-5 段落（每段 ≤300 字）+ 涉及人物的卡摘要
```

### 3.2 真实 token 预算

| 项 | 计算 | token |
| --- | --- | --- |
| 全书正文 | 51.6 万字 × 0.75 | ≈ 38.7 万（**永远不全量入 context**） |
| 单章正文 | 2061 字 × 0.75 | ≈ 1550 |
| 单章 L1 摘要 | 250 字 | ≈ 190 |
| 弧摘要 L2（10 章一弧） | 200 字 × 24 弧 | ≈ 3600（全量可塞） |
| 检索片段 | 5 × 300 字 | ≈ 1125 |
| 对话历史 | 保留最近 6 轮 | ≈ 1800 |

按 8k 窗口排布：

```
system + 规则            300
L3 总纲 + 最近 3 个 L2    1200
当前章 L1               190
当前章正文(可选，默认开)  1550
检索片段                 1125
对话历史                 1800
输出预留                 800
────────────────────────────
合计                    6965  ← 8k 窗口内有余量
```

按 12k / 32k 窗口则放开：可加前 2 章原文、检索 top-10、人物全卡。

### 3.3 检索：SQLite FTS5 + trigram

51.6 万字、15,265 段，FTS5 建索引 1–2 秒，查询毫秒级，足够，不需要向量库。

```sql
CREATE VIRTUAL TABLE seg_fts USING fts5(
  text, chapter_idx UNINDEXED, para_idx UNINDEXED,
  tokenize='trigram'          -- 中文用 trigram，避免 unicode61 不分词的坑
);
```

三个工程细节：
- **trigram 让"主角A"这种两字人名也能命中子串**，中文场景比 unicode61 实用；索引体积约为原文 3–4 倍（51.6 万字 → 约 200 MB 内，可接受）。
- 查询要先做**别名归一**：`昵称 → 主角A`、`学姐 → 角色C`，否则问"昵称是谁"检索不到。
- 人名 + 疑问词组合时，先按人名过滤再按语义扩词（`变身/觉醒/魔女` 等设定词做成同义词表）。

> 若后续要跨书、跨语言检索，再加 `sqlite-vec` 做混合检索；v1 不必。

## 4. 摘要体系：L0–L3 分级 + 增量

| 层 | 粒度 | 长度 | 生成时机 | 用途 |
| --- | --- | --- | --- | --- |
| L0 | 段落/片段 | 一句话 | 随分段生成（已有 `segment.summary`） | 分镜、检索摘要 |
| L1 | 章节 | 200–300 字 | 读完后异步 | 前情、检索增强 |
| L2 | 弧（10 章） | 200 字 | 10 个 L1 齐了触发 | 常驻上下文 |
| L3 | 全书 | 150 字 + 人物关系 | 全书 L2 齐了触发 | 常驻上下文、新读者入口 |

**map-reduce 增量**：新章只重算该章 L1、所在弧的 L2、以及 L3（L3 用旧的 L3 + 新 L2 reduce，不重读全文）。234 章全量首建约 234 次调用；此后每章只 1 次 L1。

摘要的硬性要求（写进模板，不只写进文档）：

1. **中性、不评价**：不写"精彩之处在于…"，只写发生了什么。
2. **不剧透后文**：L1 只允许使用本章及之前的 L0 信息；模板里显式禁止"后来/最终/其实"这类前瞻表述。
3. **保留专名**：人名、地名、道具名原样保留（否则后续检索打断链）。
4. **固定字段**：`who / where / what_changed / hook`，便于结构化检索与拼装。

```json
{
  "chapter": 33,
  "who": ["主角A", "角色C"],
  "where": "学院宿舍",
  "what_changed": "角色C以定制魔杖为奖励，要求主角A十天内掌握魔文组合",
  "hook": "主角A对期限感到压力",
  "summary": "……"
}
```

## 5. 对话设计

### 5.1 用工具调用，而不是纯塞上下文

纯 stuffing 在 51.6 万字的书上必然失败（问"第三章那个红发老师是谁"就检索不到）。给模型四个工具：

```python
TOOLS = [
  search_text(query, top_k=5)            -> [{chapter, para, text, score}]
  get_chapter(idx)                        -> 章节全文（限 1 章/次）
  get_summary(level, idx)                 -> L1/L2/L3
  get_character(name)                     -> 人物卡 + 出场章节 + 形态时间轴
]
```

编排：先让模型决定检索词（低温、单轮），执行检索、拼装、再回答。上限 3 次工具调用，避免死循环。

### 5.2 引用与定位

回答里的每个事实必须挂引用，格式固定为 `[ch12:p3]`，前端渲染成可点 chip：

```
角色C是主角A的学姐，用定制魔杖作为奖励逼她十天掌握魔文 [ch33:p1][ch33:p5]。
```

点击 chip → `view.goTo({index: 33, anchor: doc => doc.getElementById('p1')})` + 高亮。这和架构文档里的 `Locator` 是同一套坐标，不额外造轮子。

**硬约束：无引用的事实不许输出**。模板里写死"若检索结果不足以回答，直接说'书中未提及'，不要推测"。这是抑制幻觉最有效的一招，比调温度管用。

### 5.3 剧透锁

默认 `max_chapter = 当前阅读位置`。检索、摘要、人物卡全部按此截断：

```python
def visible_scope(session):
    return range(0, session.current_chapter + 1)
```

用户可手动解除（"允许剧透"），解除后 UI 上所有 AI 输出打"含后文内容"标记。这个开关必须显式、可回退，且状态持久化。

### 5.4 与漫画的联动

问"这一格画的是什么"时，上下文不是图，而是：

```json
{
  "page": "p033", "panel": "p033-1",
  "shot": "medium_close", "composition": "双人同框，角色C在右",
  "characters": [{"id":"moyanqiu","pose":"伸手","expr":"促狭笑"},{"id":"char_a","pose":"侧头躲","expr":"委屈"}],
  "bg": "宿舍室内，夜晚", "caption": "（示例段落）",
  "dialogue": [{"speaker":"char_c","text":"（示例对话）"}],
  "source_span": "第1章 第1-6段"
}
```

回答时要求模型**只解释已有元素**，不得新增画面细节。这条要写进模板：

> 你只能基于给定的分镜字段作答。字段里没有的元素（例如天气、第三人）一律不得提及。

### 5.5 交互位置

| 位置 | 形态 |
| --- | --- |
| 选中正文 | 浮动菜单：解释 / 这人是谁 / 前情提要 |
| 章节末尾 | 折叠卡「本章概要」+「下一章预告(不剧透)」 |
| 分镜卡 | 角标按钮「这一格在讲什么」 |
| 右下角 | 抽屉式对话，保留最近 6 轮，可清空 |
| 目录页 | 「全书梗概」+ 人物关系图 |

## 6. 提示词结构

```jinja
{# prompts/reader_chat.j2  version: 2 #}
你是这部小说的阅读助手。只依据提供的材料回答，不推测、不评价、不剧透第 {{ max_chapter + 1 }} 章之后的内容。

【当前进度】第 {{ current_chapter + 1 }} 章 / 共 {{ total_chapters }} 章
【全书梗概】{{ l3_summary }}
【最近剧情】{{ l2_summaries | join('\n') }}
【本章摘要】{{ l1_summary }}
【本章正文节选】{{ chapter_excerpt }}
【检索到的原文】
{% for hit in hits %}[ch{{ hit.chapter + 1 }}:p{{ hit.para }}] {{ hit.text }}
{% endfor %}
【涉及人物】{% for c in characters %}{{ c.name }}：{{ c.one_line }}（形态：{{ c.forms | join('→') }}）
{% endfor %}

规则：
1. 每个事实后标注 [chX:pY]，X 从 1 开始计数。
2. 材料中没有的，回答"书中未提及"。
3. 用户问到漫画画面时，只解释给定字段，不补充未给出的视觉细节。
4. 回答控制在 300 字内，先给结论再给依据。
```

`version` 与 `runs.config_snapshot` 一起存，便于回归对比。

## 7. 关键约束

| # | 约束 | 具体数字/做法 | 不满足的后果 |
| --- | --- | --- | --- |
| 1 | 上下文不能全量 | 全书 38.7 万 token，任何窗口都装不下 | 必须分层摘要 + 检索 |
| 2 | 单轮输入 ≤ 8k token | 见 3.2 预算表 | 超窗口截断，回答丢关键信息 |
| 3 | 首 token < 1.5 s | 检索 ≤100ms + 流式输出 | 读者等待感强，不如不开口 |
| 4 | 摘要必须异步 | 读完一章后台生成，不阻塞翻页 | 翻页卡顿直接毁掉阅读体验 |
| 5 | 无引用不输出 | 模板硬约束 + 后处理校验（正则要求至少 1 个 `[chX:pY]`） | 幻觉一旦出现，用户会彻底不信这个功能 |
| 6 | 默认防剧透 | `max_chapter` 截断所有检索与摘要 | 一次剧透就会毁掉阅读体验，且不可挽回 |
| 7 | 漫画解释不得越界 | 只允许使用 panel 字段 | AI 编造画面细节，与图不符 |
| 8 | 视觉模型缺位 | 本机 `models/LLM` 为空，`QwenTE_ImageInfer` 无模型可用 | 外部漫画 caption 暂不可用，需远程 VLM 或自备 GGUF |
| 9 | 隐私 | 默认本地模型；调用远程需显式开关 | 书籍内容外泄 |
| 10 | 长对话漂移 | 每 6 轮用滚动摘要替换历史 | 上下文越聊越偏 |
| 11 | 摘要不可前瞻 | L1 只能用本章及之前信息 | 摘要剧透比回答剧透更致命（自动生成、面积大） |
| 12 | 冷启动 | 新书首次打开要有 L3，否则"全书讲了什么"答不了 | 首建 234 次调用，需后台队列 + 进度条 |

## 8. 数据表补充

```sql
CREATE TABLE chapter_summaries (
  book_id TEXT, chapter_idx INTEGER, level INTEGER,   -- 1=章 2=弧 3=全书
  scope_from INTEGER, scope_to INTEGER,
  summary TEXT, fields_json TEXT,
  template_version INTEGER, model TEXT,
  created_at INTEGER,
  PRIMARY KEY (book_id, level, scope_from)
);

CREATE TABLE panel_captions (          -- 仅外部漫画需要
  panel_id TEXT PRIMARY KEY,
  caption TEXT, tags_json TEXT,
  source TEXT,                         -- storyboard | vlm | manual
  model TEXT, confidence REAL,
  created_at INTEGER
);

CREATE TABLE chat_sessions (
  id TEXT PRIMARY KEY, book_id TEXT,
  current_chapter INTEGER, spoiler_unlocked INTEGER DEFAULT 0,
  rolling_summary TEXT, created_at INTEGER, updated_at INTEGER
);

CREATE TABLE chat_messages (
  id TEXT PRIMARY KEY, session_id TEXT,
  role TEXT, content TEXT, citations_json TEXT,
  tokens_in INTEGER, tokens_out INTEGER, created_at INTEGER
);
```

## 9. 验收标准

| 项 | 标准 |
| --- | --- |
| 本章概要 | 234 章全部生成，人工抽查 10 章，事实错误 0 处、剧透 0 处 |
| 全书梗概 | 能在 800 字内说清主线（变身设定、主要人物、当前进展） |
| 划词提问 | 人名/术语类问题准确率 ≥ 90%（50 题人工评测） |
| 引用可跳转 | 100% 引用 chip 能定位到正确段落并高亮 |
| 剧透锁 | 在第 50 章提问"结局是什么"，必须拒答或提示解锁 |
| 分镜解释 | 抽查 20 格，未出现字段外的画面描述 |
| 延迟 | 首 token p95 < 1.5s；摘要后台生成不影响翻页 |
| 降级 | 文本模型不可用时，概要显示"暂不可用"，阅读功能完全不受影响 |

## 10. 落地顺序

1. **L1 摘要 + 本章概要卡**（最小可用，234 次调用，一夜跑完）
2. **FTS5 检索 + 划词提问**（复用 Locator 做引用跳转）
3. **对话抽屉 + 工具调用 + 剧透锁**
4. **L2/L3 聚合 + 全书梗概 + 人物关系**
5. **分镜解释**（读 storyboard，零额外成本）
6. **外部漫画 caption**（需补 VLM，最后做）
